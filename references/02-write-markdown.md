# 流程二：视频＋字幕 → 完整图文 Markdown 讲义

输入：可读本地视频、带起止时间的字幕。来源平台不影响本流程；只有纯文本时先解决时间对齐，不编造时间戳。

正式输出：`图文讲义.md`、`图片/`；有疑义时另附 `校对记录.md`。保留逐段覆盖记录。先完成 Markdown，不能用 notes.json 或 HTML 替代正式讲义。

## 内容要求

完整覆盖视频内容：不补充视频外的解释，不概括压缩，不省略例子和推导步骤。不另外添加总结、延伸阅读或练习题。

### 1. 按原视频顺序整理全文

读取全部字幕，保留稳定编号。逐段处理，只调整标点、断句和段落，让口语能顺畅阅读；保留原意、细节和讲解过程。标题只帮助阅读，不改变原视频讲解顺序，不把相似段落合并为概要。

原音轨为外语而用户需要中文讲义时，保留原语 ASR 原稿，逐段忠实译写中文；区分原语转写与讲义译文。画面压制字幕可辅助校对，但没有可下载字幕轨时仍归本地转写分支。翻译不增加解释、不删减赞助等原片内容，无法确认处标注。

### 2. 结合声音与画面校正字幕

核对数学术语、符号和公式。结合原片声音与画面确认识别错误；遇到无法确认的内容标注出来，不自行猜测。原始字幕保持不变，正文另行校正。原片表述有矛盾时保留并标记，详细意见放入校对记录，不补写新证明。未完成逐句听音时如实说明。

### 3. 按讲解需要插入截图

定义、图示、公式、操作步骤和动画中的关键变化都保留。连续构造或推导用多张截图展示过程，不只留最终画面。

可以先按每 5～10 秒生成缩略预览，再定点选取清晰原图。根据内容密度调整，不固定截图数量。预览只用于筛选，不等于逐帧覆盖；字幕提到却未见的画面要定点补查。小字与公式查看原图。过渡动画不完整时调整截图时间，图注必须使用实际截图时间。

```bash
ffmpeg -ss 123 -i '视频.mp4' -frames:v 1 -q:v 2 '图片/02-03.jpg'
```

截图使用项目内相对路径，保留原视频画面，不用生成图片替代。

### 4. 逐段检查覆盖情况

按[疑点复核与讲解点覆盖](quality-review.md)先从源内容列出具体讲解点，再给出正文中实际承载该点的句子。一个例子中的数值、否定条件、操作次序、原因与结果分别核对，不用章节标题或时间范围代替正文证据。

画面独有的公式、标注、代码与中间态另列 visual_units，并记录原图细节检查或仅缩略预览。用 check_coverage.py 检查源编号遗漏、排除矛盾、引文失效和图片缺失；文字、画面和声音的核对状态分别记录。结构检查通过不等于语义或听音通过，待核对项继续保留。

明显无意义的识别残片可以排除，但须记录字幕编号、原文与理由，不能借此删减视频内容。未核对的声音或画面如实说明。

## Markdown 结构

按“小节标题＋时间范围＋完整讲解＋对应截图”排列：

```markdown
# 视频标题

来源：[原视频](https://example.com/video)

## 一、小节标题

00:50—01:06

按视频顺序整理的完整讲解。行内公式写成 \(x\in C\)。

\[
C=\bigcap_{n=1}^{\infty}C_n
\]

![原视频画面 01:05](图片/01-05.jpg)

*原视频 01:05*
```

时间为普通文字，不加跳转链接。公式用真正的 TeX：行内 `\( ... \)`；独立公式 `\[ ... \]` 单独成段。分数、上下标、极限与交集不用 Unicode 字符拼凑。只改变排版，不改数学含义。

使用标准 Markdown 标题、正文、图片、链接和必要强调；不要在正文中混入原始 HTML。完成正文和覆盖核对后，用户需要导出格式时进入 [流程三](03-export.md)。
