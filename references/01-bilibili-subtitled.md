# B 站有平台字幕：获取本地材料

本流程只负责取得本地视频与字幕。下载视频成功不代表匿名字幕请求也会成功。

## 1. 建立项目、检查工具

从 URL 提取 BV 号，去掉与视频定位无关的跟踪参数。按用户指定位置新建目录，例如 `视频讲义实验-BVxxxx`。检查 yt-dlp、FFmpeg、ffprobe；已有工具直接复用。若缺少工具，用可信来源和当前环境允许的方式准备，不要求全局安装。下载／联网受限时按环境审批机制处理。

查 yt-dlp 当前文档或帮助，避免硬编码本次视频的格式编号。可用：

```bash
yt-dlp --no-playlist --dump-single-json --skip-download '视频链接'
yt-dlp --no-playlist --list-subs '视频链接'
```

仅输出标题、时长、画质等必要元数据，不把完整媒体签名地址、Cookie、个人信息输出给用户。元数据中的 aid、cid 必须来自目标视频实际响应；多 P 视频确认用户要哪一 P。

## 2. 下载视频

按可用格式选择足以看清文字的画质，优先 1080p，但不把它当成所有视频必需条件：

```bash
yt-dlp --no-playlist -f 'bv*[height<=1080]+ba/b[height<=1080]' \
  --merge-output-format mp4 -o '项目目录/%(title)s.%(ext)s' '视频链接'
```

若音画分开，使用 FFmpeg 合并。先确保新文件有视频流、音频流、合理时长，再清理本次生成的冗余分轨；不删除用户已有材料。请求的视频无音轨时按实际情况说明。验证下载完成状态，必要时做解码检查。

## 3. 区分“无字幕”与“需要登录”

`danmaku` 是弹幕，不能当作字幕。未登录返回空字幕列表或提示登录时，不宣称该视频没有字幕。

有可读的本地登录会话且用户授权当前视频任务时，可用 `--cookies-from-browser` 或本机 Cookie 文件。不要让用户把 Cookie 发进聊天。

**Chrome Cookie 解密失败时，优先复用已登录 Chrome 页面**：

1. 用可用浏览器工具发现并绑定对应视频页面，确认页面实际登录状态。
2. 从已取得的目标视频元数据读 aid、cid。在同一浏览器的新临时标签打开播放器信息接口。本次验证过的形式为：

   `https://api.bilibili.com/x/player/wbi/v2?aid=实际aid&cid=实际cid`

3. 浏览器自动携带适用 Cookie。接口可能变化或要求签名；这只是已经验证过的形式，不是永久承诺。读取页面返回的 JSON，检查 code、目标 bvid/cid、`data.subtitle.subtitles`，仅保留必要字幕信息。响应还可能含账号与 IP 信息，不转存整份响应到项目。
4. 按 `lan` / `lan_doc` 选择中文轨，保留实际轨道类型，例如 `ai-zh` 不应标成人工字幕。`subtitle_url` 以 `//` 开头时补 `https:`。
5. 用有效字幕 URL 下载字幕 JSON。此前实验中这一步无需 Cookie，但 URL 本身有临时授权参数；不要把它写入讲义或技能，也不承诺永远无需 Cookie。必要时设置 B 站 Referer 和常规 User-Agent。
6. 检查 JSON `body` 非空，字段有 `from`、`to`、`content`。运行规范化脚本，并比较首末时间与视频时长。

不通过页面 JavaScript 导出 Cookie，也不需要先解密浏览器的 Cookie 数据库。浏览器 UI 工具不支持直接请求时，可像本次一样导航到接口 JSON 页面读取；不要在只允许只读 DOM 的 evaluate 接口里偷偷使用 fetch 或访问隐藏应用状态。

## 4. 输出与停止条件

项目内保留视频、原始字幕 JSON、规范字幕 JSON、SRT、文字稿。记录标题、BV 号、时长和字幕来源类型，不记录临时下载签名或登录凭证。

若遭遇登录失效、验证码、访问限制或接口持续失败，报告具体卡点，并只请求完成当前缺失步骤所需的用户操作。不要盲目重试或把失败替换成弹幕；不要在未说明情况下转为语音识别。本流程到材料齐全为止；用户还要求写讲义时，转入 [流程二](02-write-markdown.md)。
